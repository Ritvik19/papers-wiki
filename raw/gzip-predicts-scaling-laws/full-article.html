Papers Explained: gzip Predicts Data-dependent Scaling Laws

Scaling laws for neural language models are not agnostic to the training data, but instead are sensitive to data complexity. By generating datasets with varying syntactic complexity and measuring their gzip-compressibility, the study finds that less compressible (more complex) data shifts the compute-optimal scaling law to favor larger datasets over more parameters; thus, compressibility predicts how scaling laws change, enabling more efficient compute allocation, and real-world data like code and text follow these trends with substantial compute savings possible by adjusting for data complexity

Modulating Data Complexity using PCFGs

Probabilistic Context-Free Grammars (PCFGs) extend traditional context-free grammars (CFGs) by assigning probabilities to their production rules. This lets them model the ambiguity and variability of natural language quantitatively. The grammar generates trees where each node is a syntactic category, and edges represent production rules used to form sentences. When generating sentences, rules are probabilistically sampled and applied until tree leaves are terminals (i.e., actual vocab tokens)

PCFGs allow modulation of dataset complexity via their syntactic properties. The PCFG have certain parameters:

  • Number of terminals (actual tokens)
  • Number of non-terminals (syntactic categories)
  • Maximum length of the right-hand side (RHS) of production rules
  • Maximum number of productions (RHS options) per non-terminal Increasing these values increases syntactic complexity.

All these rules are gathered and the grammar is instantiated using the PCFG package built on NLTK. To generate a dataset, the PCFG is used to sample sentences probabilistically. In these synthetic datasets, terminals are represented by integers that serve directly as token IDs for the LM. Sentences end with a special integer 0.

This approach allows to generate multiple datasets with different levels of syntactic complexity, just by changing the grammatical constraints used for each PCFG.

Using 6 sets of grammatical constraints, 6 datasets of token sequences with varied complexity are created.

Measuring Syntactic Complexity with gzip-compressibility

To compare the complexity of these PCFG-generated datasets (and possibly real-world datasets), a metric is needed. While one could use a measure based directly on the PCFG’s syntactic properties, this only works for datasets where the grammar is known. For real-world data (e.g., web text), deducing the grammar is computationally challenging.

Instead, the method chosen is to estimate complexity using gzip compression. This is based on theoretical work equating compressibility (how well you can compress something) with information entropy, and entropy with syntactic complexity. For each dataset, 1000 token sequences are sampled, compressed with gzip, and the ratio of the compressed size to the original size is measured. The median and standard deviation of these ratios are computed.

  • As the grammatical parameters (non-terminals, terminals, production rule options/length) increase, datasets become harder to compress.
  • Higher syntactic complexity leads to less compressibility (larger ratios), confirming the connection between grammar complexity and gzip-compressibility.
  • Some synthetic datasets, depending on their properties, resemble code (which is easier to compress) while others resemble natural language in their complexity.

Are Scaling Laws Sensitive to Data Complexity?

To identify the scaling law for a dataset, models of various sizes (4.2M, 8.8M, 20.3M, 59.0M, 275.3M, 1.4B) are trained on differently sized data subsets (100K, 1M, 5M, 20M, 50M, 100M tokens) A power law is fitted to training runs’ final losses. Models are trained with a batch size of 32, in a single epoch, using AdamW optimizer, starting learning rate 5e-5, with cosine decay. 

  • More complex (less compressible) datasets make models converge slower regardless of their size.
  • More compute is needed to model more complex data; thus, data complexity impacts scaling fundamentally.
