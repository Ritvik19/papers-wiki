Papers Explained: Is Grep All You Need

This paper reports an empirical study comparing grep and vector retrieval on a 116-question sample from LongMemEval, using a custom agent harness (Chronos) and provider-native CLI harnesses (Claude Code, Codex, and Gemini CLI), for both inline tool results and file-based tool results that the model reads separately and while progressively mixing in additional unrelated conversation history, so that each query is embedded in more distracting material alongside the passages that matter. It finds that grep generally yields higher accuracy than vector retrieval, while overall scores still depend strongly on which harness and tool-calling style is used, even when the underlying conversation data are the same.

Methodology

A 116-question subset from the LongMemEval benchmark is used, which tests agents on multi-session conversations. Each question includes sessions: one or more “oracle sessions” (with required information) and a variable number of “distractor sessions” (irrelevant). Questions cover six categories:

  • Knowledge-update (tracking changes over time)
  • Multi-session (integrating data across sessions)
  • Single-session-assistant (recalling model-generated content)
  • Single-session-preference (user personal preferences)
  • Single-session-user (facts stated by user)
  • Temporal reasoning (calculating durations, sequences, and dates)

Retrieval Implementations

  1. Lexical Search (Grep): Uses regex to match over conversation turns and extracted events, scored by count, results returned.
  2. Semantic Search (Vector): Populates indexes with embedded turns and events. Query is embedded and most relevant entries are retrieved via approximate nearest-neighbor search. Includes a reranking step for top-k passages (k selected by agent)

Agent Harnesses

Custom Harness (Chronos)

Built on LangChain, agent has access to four tools: grep and vector search over turns/events, and grep for programmatic mode. Tools are enabled/disabled depending on experiment config. Dynamic prompts are used tailored to the question type. Each episode starts with category-specific guidance and initial broad context (top-15 vector results). The tool-calling loop continues until the agent gives a final answer.

Provider-Native CLI Harnesse

Three agents tested via CLI, with dynamic search strategies and access to bash-callable scripts for grep/vector search.

Tool-Calling Architectures

  1. Standard (Inline): Scripts print results to stdout, appended to agent context. Results compete with prompts and history for context window space.
  2. Programmatic (File-Based): Results written to an accessible file; agent reads/searches files explicitly. Decouples result size from context window constraints; forces agents to choose which results to use.

Models Evaluated

  • Claude Opus 4.6, Claude Haiku 4.5
  • GPT-5.4
  • Gemini 3.1 Pro, Gemini 3.1 Flash-Lite

Evaluation Protocol

Evaluation follows LongMemEval’s protocol: uses GPT-4o as the grader, which receives question, reference answer, and agent hypothesis; outputs binary judgment with category-specific instructions.

Experiment 1: Retrieval Mode, Harness, and Tool Calling Method

Inline lexical retrieval (grep) outperforms inline dense retrieval (vector) across all harness–model pairs:

  • Largest margin: Chronos with Gemini 3.1 Flash-Lite (86.2% vs. 62.9%).
  • Smallest margin: Claude Code with Claude Opus 4.6 (76.7% vs. 75.0%).

Accuracy varies substantially by harness, even for the same underlying model:

  • Claude Opus 4.6 achieves 93.1% under Chronos but only 76.7% under Claude Code, indicating harness-level effects are as significant as retrieval mode effects.

Programmatic (file-based) delivery reshuffles retrieval mode effectiveness:

  • Programmatic vector exceeds programmatic grep in 5 out of 10 harness–model pairs (e.g., Chronos with Claude Opus 4.6, Codex with GPT-5.4, Gemini CLI with Gemini 3.1 Flash-Lite), showing context bandwidth and agent competence are critical.
  • In some cases, programmatic grep accuracy drops sharply (e.g., Codex with GPT-5.4: 93.1% inline grep vs. 55.2% programmatic grep).

Lexical and dense search optimize different failure modes:

  • Lexical (grep): High precision, but sensitive to vocabulary mismatch.
  • Dense (vector): Broader, surfaces paraphrases but risks distracting semantically similar but irrelevant results.
  • Dense retrieval suffers more on weaker backbones due to less consistent query refinement and reranker-aware reading.

Experiment 2: Context Scaling with Increasing Noise

The session limit per question (labelled s5, s10, s20, s30, full) is varied to stress-test retrieval robustness. 

  • The accuracy of both retrieval families does not degrade in parallel or monotonic fashion as noise increases: vector accuracy often peaks at a lower session count and drops at higher limits, while grep may close the gap or even overtake later depending on the model (e.g., Chronos Opus is vector-ahead at some session counts but grep overtakes at others).
  • Persistent model/harness-specific patterns were observed: Claude Code consistently favored grep, Gemini CLI Pro consistently favored vector, and Chronos exhibited crossover points, which could result from differences in provider tooling, logging, and tokenization conventions.
  • The full vendor-complete picture is incomplete due to pending intermediate results for Codex; thus, conclusions about relative scaling remain conditional.
