Papers Explained 409: Jina Embeddings v4

Jina Embeddings v4 is a 3.8 billion parameter multimodal embedding model that unifies text and image representations through a novel architecture supporting both single-vector and multi-vector embeddings in the late interaction style. The model incorporates task-specific Low-Rank Adaptation (LoRA) adapters to optimize performance across diverse retrieval scenarios, including query-based information retrieval, cross-modal semantic similarity, and programming code search.

The model is available on HuggingFace.

Model Architecture
Architecture of Jina Embeddings v4.
The architecture of Jina Embeddings v4 uses the Qwen2.5-VL model as a backbone. Like Qwen2.5-VL, it supports two input modalities, text and image, and processes its inputs in the same way. However, Jina Embeddings v4 has extended the architecture to support two output options: single-vector and multi-vector, and adds LoRA extensions to improve task-specific performance.
Basic specifications of Jina Embeddings v4.
Dual Mode Output

Jina Embeddings v4 offers a choice between traditional 2048-dimensional single-vector embeddings (which can be truncated to 128 dimensions with minimal loss due to Matryoshka Representation Learning) and ColBERT-style multi-vector embeddings for late interaction.

Single-vector embeddings are generated by mean pooling the final layer of the base model.

Multi-vector embeddings are unpooled token-level representations (128-dimensional each) proportional to the number of input tokens, directly comparable to ColBERT/ColPali outputs, and are generated via an additional projection layer.

Task Specialization with LoRA

Following the methods used for Jina Embeddings v3, three task-specific LoRA adapters have been implemented for different information retrieval use cases:

Asymmetric Query-Document Retrieval
Semantic Similarity and Symmetric Retrieval
Code (i.e., computer programming language) Retrieval

Each LoRA adapter set has only 60M parameters, so maintaining all three adds less than 2% to the memory footprint of Jina Embeddings v4.
Supported tasks of Jina Embeddings v4.
Training

The training process involves initializing model weights based on Qwen/Qwen2.5-VL-3B-Instruct, with random initialization for the multi-vector projection layer and LoRA adapters. The backbone model’s weights remain fixed, while LoRA adapters modify the backbone and projection layer. Training occurs in two phases:

A single LoRA adapter is trained using contrastive text and text-image pairs, employing the InfoNCE loss function for both single-vector and multi-vector similarity. No task-specific training is done here.
The resulting LoRA adapter is duplicated into three task-specific adapters, each then trained individually with task-specific text and text-image triplets.

In both phases, Matryoshka loss is applied alongside the base loss to ensure single-vector embeddings can be truncated.

Pair Training

The training process begins with a contrastive objective where the model learns to embed related input pairs (text-text or text-image) closer together and unrelated pairs further apart. In each step, two batches are sampled:

Btext (text pairs)
Bmulti (text-image pairs)

Single-vector and multi-vector embeddings are generated for all texts and images. Similarity matrices Sdense(B) and Slate are constructed using cosine similarity for single-vector embeddings and a modified late interaction similarity score for multi-vector embeddings, respectively.

The choice of loss function requires a normalized score, so the late interaction score is divided by the number of tokens in the query.

This modification is only for training. For retrieval applications, normalization is not necessary since the query is invariant.

The InfoNCE loss function (LNCE) is applied to each of the four similarity matrices.

To account for error distribution differences between single-vector and multi-vector embeddings, a weighted Kullback–Leibler divergence (DKL) of the softmax-normalized similarity scores is added.

The text-text pairs are selected and filtered using the Jina Embeddings v3 method. Unlike typical image-caption or query-image pairs, the text-image data includes images generated from diverse document types like website screenshots, rendered Markdown, charts, and tables, representing real-world content. The text queries accompanying these images consist of questions, keywords, key phrases, long descriptions, and factual statements.

Task-Specific Training

Asymmetric Retrieval Adapter

Asymmetric retrieval assigns substantially and qualitatively different embeddings to documents and queries, even if they happen to have the very same text. Having distinct encoding mechanisms for the two often significantly benefits embeddings-based retrieval performance. This can be achieved either by training two separate adapters or by employing two distinct prefixes, so that embedding models can readily distinguish them when they generate embeddings. The prefix method has been used for Jina Embeddings v4. Previous work shows little benefit from combining both methods.

The training data includes hard negatives: triplets of a query, a matching document, and a semantically similar but incorrect document. For each query-positive pair (qi, pi) in a batch B, all other documents pj (where j ≠ i) in the batch are treated as negatives for qi. These additional negatives are incorporated into the training process using an extended version of the LNCE loss (LNCE+)

The dataset of text hard negatives is similar to that used to train Jina Embeddings v3. Multimodal hard negatives are created using existing datasets like Wiki-SS and VDR multilingual, as well as mined from curated multimodal datasets.

Text Matching Adapter

For these symmetric tasks, training data with ground truth similarity values is the most effective.

The model utilizes the CoSENT loss function

This loss function operates specifically on two pairs of text values, (q1,p1) and (q2,p2), for which the ground truth similarity is known.

To train the model with this objective, semantic textual similarity (STS) training datasets like STS12 and SICK are employed. The training data is augmented with pairs that do not have pre-defined similarity scores. For these pairs without known scores, the training proceeds identically to the pair training, utilizing the standard InfoNCE loss.

Code Adapter

Code embeddings in Jina Embeddings v4 are specifically designed for natural language-to-code retrieval, code-to-code similarity search, and technical question answering, recognizing code as a specialized text requiring distinct data sources. Training the code retrieval LoRA adapter does not affect the vision portion of Jina Embeddings v4. The backbone LLM, Qwen2.5-VL, already possessed some code embedding capacity due to pre-training on datasets like StackExchangeQA and CodeSearchNet. LoRA training employed the same triplet-based method, using training triplets derived from CodeSearchNet, CodeFeedback, APPS, and the CornStack dataset.

Jina-VDR: Visually Rich Document Retrieval Benchmark

To evaluate the performance of Jina Embeddings v4 across a broad range of visually rich document retrieval tasks, a new benchmark collection has been produced. It extends the ViDoRe Benchmark by adding a diverse collection of 30 datasets spanning a broad range of domains (e.g. legal texts, historic documents, marketing materials), covering a variety of material types (e.g. charts, tables, manuals, printed text, maps) and query types (e.g. questions, facts, descriptions), as well as multiple languages. These additional tests are sourced from three main categories: re-purposed existing datasets, new manually-annotated datasets, and generated synthetic data.

Overview of the Dataset Collection.

Re-purposed Datasets

Existing VQA and OCR datasets were adapted, modified, and restructured into appropriate query-document pairs.

For DonutVQA, TableVQA, MP-MQA, CharXiv, and PlotQA, structured templates and generative language models were used to formulate text queries matching their contents.
JDocQAJP and HungarianDocQA already contained documents and queries in forms requiring minimal processing for adaptation.
OurWorldInData and WikimediaMaps datasets use encyclopedia article fragments and image descriptions as queries to match with charts and maps.
GitHubREADMERetrieval contains rendered Markdown pages from GitHub README files, paired with generated natural language descriptions in 17 languages.
WikimediaCommonsDocuments pairs multilingual document pages with paragraph-level references extracted from Wikipedia.

Manually Annotated Datasets

A number of human-annotated resources were curated to better reflect real-world use cases. Documents in these datasets were paired with carefully written human queries, without template-based phrasing, to capture genuine information-seeking intent.

Academic slides from Stanford lectures.
Educational figures in the TQA dataset.
Marketing and institutional documents such as the Jina AI 2024 Yearbook, Japanese Ramen and the Shanghai Master Plan
ChartQA and its Arabic counterpart, ArabicChartQA, which specifically focus on charts and infographics.

Synthetic Data Generation

This method addresses the common lack of diversity in information retrieval benchmarks, using generative AI to fill gaps where human annotation is not feasible.

Datasets from primarily European sources (scans of historical, legal, and journalistic documents) in German, French, Spanish, Italian, and Dutch were used, with queries generated by Qwen2.
HindiGovernmentVQA and RussianBeverages datasets were handled similarly, adding underrepresented languages, public service documents, and commercial catalogs to the benchmark set.
TweetStockRetrieval is a collection of chart-based financial data paired with multilingual template-based generated queries.
AirBnBRetrieval is a collection of rendered tables paired with queries in 10 languages generated from a template.
In several cases, such as TableVQA, bilingual examples were introduced to better assess cross-lingual retrieval performance, with questions and answers synthesized using advanced multilingual LLMs like Gemini 1.5 Pro and Claude 3.5 Sonnet.
