Papers Explained: IFBench

Following human instructions precisely including strict output constraints is critical for language model performance, but most models only excel at a narrow set of familiar benchmarks like IFEval and fail to generalize to new, diverse constraints. The authors introduce IFBENCH with 58 novel constraints and 29 additional training constraints, and show that RLVR, especially when using mixed and complex constraint setups, significantly improves both in-domain and out-of-domain instruction following, though it can also lead models to over-prioritize constraints over task intent.

The project is available on GitHub.

IFBench

IFBENCH is a new benchmark and paradigm designed to evaluate the generalizability of methods for precise instruction following. It introduces a taxonomy of constraint templates, which are divided into training and test constraints to avoid contamination. The constraints were manually created sourced from LM user feedback on constraint types, or written directly to cover essential instruction-following skills. Only constraints that can be paired with a Python-based verification function ensuring reproducibility were included.

IFBENCH features 58 new verifiable constraints, expanding on the 25 from IFEval. These are used to create test prompts by combining unseen, held-out prompts from WildChat with unseen constraints, helping to prevent data leakage between train and test sets, and thus more accurately evaluating language models’ generalization in precise instruction following. Each prompt-constraint pair was human-annotated to ensure compatibility. The 58 constraints fall into 7 broad categories: count, ratio, words, sentence, format, custom, copy. The final benchmark has 300 prompts and includes particularly challenging constraints and each IFBench instruction contains either one or two constraints

Accuracy is measured in two ways: strict accuracy (whether the constraint is followed precisely) and loose accuracy (which allows minor formatting variations, such as removing extra lines or font modifiers).

Evaluation occurs in two settings:

  • Single-turn: The prompt combines a general task (t) and one or more output constraints (c). The model must complete the task while adhering to the constraints.
  • Multi-turn: The constraint (c) is presented separately in a three-turn dialogue first, a general task prompt; second, the model’s initial response; third, a user asking for the response to be rewritten to meet the constraint. The model must rewrite the response based on all previous context.

IFTrain

FTRAIN consists of 29 new, unseen, verifiable constraints, with their corresponding verification functions. This more than doubles the current set of train constraint type. The constraints were created to capture the basic building blocks of classic constraints. 

IF RLVR

The prompts for verifiable IF training are created by combining an instruction from a public SFT dataset with a constraint from either the IFEval taxonomy or a new unseen training constraint taxonomy. Prompts are randomly sampled from TÜLU-3-SFT and at least one and up to n constraints are appended. About 60k-100k prompts are created for most experiments.

Experiments are conducted using the following base policies: Llama-3.1-Tulu-3–8B-DPO, Llama-3.1–8B, Qwen2.5–7B, Qwen2.5–7B-instruct, OLMo2, and OLMo2-instruct. Training is performed using the GRPO implementation in open-instruct with the following hyperparameters: max_token_length=2048, temperature=1, learning rate=5e-7, 16 samples per prompt, 8 GPUs (H100) and a local mini-batch size of 32. Prompt-level loose accuracy is reported for both IFEval and IFBENCH.

  • The IF-RLVR trained models outperform most of the current state-of-the-art models (besides o3). The recipe can be successfully applied to 3 different model families: OLMo, Qwen 2.5, and Llama 3.1.
